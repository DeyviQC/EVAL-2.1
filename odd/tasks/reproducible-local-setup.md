# Reproducible local setup for EVAL
Objective: make a fresh Windows checkout runnable by the five-person team without publishing machine-local secrets or generated dependencies.
Branch: `feat/reproducible-local-setup` | Delivery: `ask-on-risk` (current forecast: ~500 authored lines; delivery shape undecided) | Checks: PowerShell bootstrap validation, frontend checks, runtime status/start smoke checks.

## Specs

1. **S1 — Team workflow.** Support the request: "vamos atrabajar en equipo yo me encargare de horarios y hacistencia somos 5 en el equipo y lo aremos en el repo tambien dime como podriamos trabjar sera en ramas y un merge ? al final o como vamos a realizarlo mis otros compañeros trabajaran otras partes". Acceptance: document a simple branch and pull-request workflow suitable for five first-time collaborators, including integration order and conflict prevention.
2. **S2 — Runnable local environment.** Support the request: "tambien quiero que prepares todo el entorno para poder correrlo en mi maquina y ver la pagina y correrlo". Acceptance: a fresh supported Windows checkout can prepare its ignored local runtime, install locked dependencies, build the frontend, provision EVAL, and open the real page using documented commands.
3. **S3 — Reproducible team bootstrap.** The selected scope is: "Prepararlo para todo el equipo (recomendado)". Acceptance: repository-tracked automation and documentation allow each teammate to prepare their own machine without copying another user's encrypted local state.
4. **S4 — Commit hygiene.** Resolve: "nose si aparte nose si luego eso no se sube al comit". Acceptance: generated dependencies, database files, credentials, certificates, browser profiles, and other private runtime files remain ignored; only reusable scripts, tests, and documentation are eligible for commit.
5. **S5 — Safety assumption.** Assumption: setup must remain user-scoped on Windows, avoid administrator privileges and global certificate trust, use pinned upstream artifacts with integrity verification, and avoid deleting or replacing an existing `.local/runtime` unless the user explicitly authorizes it.
6. **S6 — Agent acceleration.** Support the request: "utiliza todos los agentes para que terminar mas rapido los agentes que tenemos asigandos tanto de gpt y de opencode go". Acceptance: delegate independent documentation and verification work to every relevant available configured agent role without overlapping write surfaces or invoking unrelated review/fix agents.
